인터넷이 전혀 연결되지 않은 폐쇄망 PC에서도 사용할 수 있는
**"완전 오프라인 업무자료 검색기"**를 만들어주세요.

개발자가 아닌 일반 직원도 사용할 수 있어야 하며, 별도의 프로그램 설치 없이 HTML 파일을 더블클릭해서 실행할 수 있도록 만들어주세요.

HTML, CSS, JavaScript 및 필요한 라이브러리를 모두 포함하여 최종 결과물은 단 1개의 HTML 파일이어야 합니다.

외부 인터넷 연결, CDN, API, 서버, Google Drive, Firebase 등은 절대 사용하지 마세요.

1. 가장 중요한 조건: 완전 오프라인

이 프로그램은 인터넷이 완전히 차단된 폐쇄망 PC에서 사용합니다.

따라서 다음 조건을 반드시 지켜주세요.

외부 CDN 사용 금지
외부 JavaScript 파일 사용 금지
외부 CSS 사용 금지
외부 폰트 사용 금지
API 호출 금지
서버 통신 금지
인터넷 연결 여부와 관계없이 모든 기능이 작동해야 함

특히 .hwpx 파일 처리를 위해 필요한 JSZip 라이브러리를 CDN으로 불러오지 말고 JSZip 3.10.1의 minified 코드를 HTML 내부 <script> 태그에 직접 포함해주세요.

즉,

형식은 절대 사용하지 말고,

형태로 HTML 자체에 포함해주세요.

최종 HTML 파일 하나만 다른 컴퓨터로 복사해도 모든 기능이 작동해야 합니다.

2. 프로그램 목적

경찰·공공기관 내부 업무자료를 개인 PC에서 검색하기 위한 프로그램입니다.

사용자가 가지고 있는 업무자료를 등록하면 내용을 추출하여 브라우저 내부 저장소에 저장하고,

검색어를 입력하면 등록된 모든 문서에서 해당 내용이 들어간 자료를 빠르게 찾아주는 방식입니다.

자료가 외부 서버로 전송되는 일은 절대 없어야 합니다.

화면에 다음 문구도 표시해주세요.

"등록된 자료는 외부 서버로 전송되지 않고 현재 브라우저 내부에만 저장됩니다."

드래그앤드롭 등록도 가능하면 추가해주세요.

4. HWPX 지원

HWPX 파일은 ZIP 기반 문서이므로 HTML 내부에 포함된 JSZip을 이용해 압축을 해제해주세요.

HWPX 내부의 다음 XML 파일들을 자동으로 찾아주세요.

Contents/section0.xml
Contents/section1.xml
Contents/section2.xml
...

section 파일 개수가 몇 개이든 자동으로 탐색해야 합니다.

특정 section0.xml만 읽도록 만들지 마세요.

모든 section*.xml 파일을 읽어서 하나의 문서 내용으로 합쳐주세요.

XML은 DOMParser를 사용하여 분석해주세요.

특히 다음 태그의 텍스트를 추출해주세요.

hp:t

예:

hp:t112 신고 접수 시 현장 출동</hp:t>

위 텍스트가 검색 가능한 데이터로 저장되어야 합니다.

가능하면 다음과 같은 경우에도 텍스트 순서가 자연스럽게 유지되도록 처리해주세요.

여러 문단
표 내부 텍스트
여러 section
줄바꿈

XML namespace 때문에 querySelector("hp:t")가 제대로 작동하지 않는 경우를 대비해서

getElementsByTagNameNS("*", "t")

또는 동일한 방식으로 namespace에 관계없이 t 요소를 탐색할 수 있도록 구현해주세요.

HWPX 분석이 실패하면 프로그램 전체가 멈추지 않도록 try-catch를 사용하고

alert 창으로 다음과 같이 알려주세요.

"HWPX 파일을 분석하지 못했습니다.
파일이 손상되었거나 지원하지 않는 형식일 수 있습니다."

5. HWP 파일은 지원하지 않음

기존 .hwp 파일은 지원하지 않습니다.

사용자가 다음과 같은 지원하지 않는 파일을 등록하면 반드시 alert를 띄워주세요.

.hwp
.pdf
.doc
.docx
.xls
.xlsx
기타 미지원 확장자

경고 문구:

"지원하지 않는 파일입니다.

지원 파일:
TXT / CSV / MD / HWPX

기존 HWP 파일은 한글 프로그램에서 HWPX 형식으로 저장한 후 등록해주세요."

지원하지 않는 파일을 조용히 무시하지 마세요.

6. 한글 인코딩 깨짐 방지

TXT, CSV, MD 파일은 한글이 깨지지 않도록 처리해주세요.

파일을 ArrayBuffer 형태로 읽은 다음 TextDecoder를 이용해주세요.

먼저 UTF-8로 읽어보고 한글이 심하게 깨졌다고 판단되면 EUC-KR 또는 CP949 방식으로 다시 디코딩해주세요.

가능하면 다음 인코딩을 지원해주세요.

1순위 UTF-8
2순위 EUC-KR / CP949

한글 깨짐 판단을 위한 간단한 로직도 구현해주세요.

예:

  문자가 지나치게 많은 경우
비정상적인 제어문자가 많은 경우

UTF-8 해석이 비정상적이면 EUC-KR로 다시 읽어주세요.

7. IndexedDB 영구 저장

파일 내용을 브라우저의 IndexedDB에 저장해주세요.

localStorage는 절대 사용하지 마세요.

DB 이름 예시:

OfflineWorkSearchDB

Object Store:

documents

각 문서는 최소 다음 데이터를 저장해주세요.

id
fileName
extension
content
fileSize
createdAt
updatedAt

가능하면 파일의 마지막 수정시간도 저장해주세요.

IndexedDB version upgrade 처리도 구현해주세요.

예:

indexedDB.open("OfflineWorkSearchDB", 1)

DB 초기화 실패, 저장 실패, 읽기 실패 등이 발생하면 프로그램이 멈추지 않게 try-catch 또는 onerror 처리를 하고 alert를 띄워주세요.

예:

"브라우저 내부 저장소를 사용할 수 없습니다."

8. Storage Persistence

가능한 브라우저에서는 다음 기능을 사용해주세요.

navigator.storage.persist()

브라우저가 영구 저장을 허용하는 경우 IndexedDB 데이터가 자동 정리될 가능성을 낮추기 위함입니다.

단, 이 기능을 지원하지 않는 브라우저에서도 프로그램이 정상 작동해야 합니다.

현재 영구 저장 허용 여부를 화면에 표시해주세요.

예:

저장 보호: 활성화
또는
저장 보호: 브라우저 정책에 따름

9. 중요: 백업 / 복원 기능

IndexedDB는 브라우저 데이터를 사용자가 직접 삭제하면 없어질 수 있으므로 자료를 별도로 백업할 수 있게 해주세요.

"전체 백업" 버튼을 만들어주세요.

백업을 누르면 현재 IndexedDB에 등록된 자료 전체를 하나의 JSON 파일로 다운로드해주세요.

예:

업무자료검색기_백업_2026-08-11.json

그리고

"백업 복원"

버튼도 만들어주세요.

백업 JSON 파일을 선택하면 기존 IndexedDB로 다시 복원할 수 있게 해주세요.

복원 시

기존 자료 유지 후 추가
기존 자료 전체 삭제 후 복원

두 가지 중 선택할 수 있도록 confirm 창 또는 UI를 제공해주세요.

백업 JSON 파일이 올바른 형식이 아니면

"올바른 업무자료 검색기 백업 파일이 아닙니다."

라고 안내해주세요.
